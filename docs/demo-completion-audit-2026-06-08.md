## 1. 원안 재해석

원안의 핵심은 `AI 브랜드 생성 데모`가 아니라 `예비점주가 프랜차이즈 상담 전에 자기 자본으로 만들 수 있는 브랜드 창업안을 검증하고, 막히는 순간 상담으로 전환되는 체험`이다.

따라서 오픈채팅에 올릴 1차 체험 데모의 기준은 다음이다.

| 기준 | 데모에서 보여야 하는 것 | 구현 판단 |
| --- | --- | --- |
| 예비점주 입력 | 예산, 개점 희망 기간, 지역, 업종, 운영 형태, 월 목표소득 | 입력 화면에 존재하지만 전체 상태 전파 약함 |
| 가상 브랜드 | 업종 선택 즉시 브랜드명, 콘셉트, 이미지, 메뉴, 가격, 원가가 생성 | 골격 존재, KIE 실생성 재검증 필요 |
| 프랜차이즈 비교 | 같은 업종 프랜차이즈 평균과 내 브랜드안을 과장 없이 비교 | 현재 가장 부족 |
| 입지 분석 | 선택 지역 후보 입지 3~5곳, 상권/SBIZ365/Kakao 지도/경쟁도/매출 추정 | 부산대 5개 후보 기준 가능 |
| 4개월 회계 | 1~4개월 매출, 원가, 인건비, 임대료, 배달비, 현금잔고, BEP | 데이터는 있으나 입지 선택과 연결 약함 |
| 타임테이블 | 개점 희망 기간별 해야 할 일, 상담/계약/시공/오픈 준비 일정 | 기본 데이터 존재, 입력값 연동 필요 |
| 상담 CTA | 상담 전 질문지, 삥 방지 체크리스트, 시공 RFP, 전화/메일 리드 저장 | 구조 존재, 전환 위치 보강 필요 |
| 점주 전환 | 개점 후 대시보드 3개월 무료 미리보기와 의견 수집 | 데모 데이터 존재, 설득 배치 보강 필요 |

## 2. 데모 범위 결정

### 2-1. 1차 내부 개발 범위

1차는 `점포 1곳만 고정`해서 끝까지 완성한다.

| 항목 | 결정 |
| --- | --- |
| 고정 시나리오 | 부산대 장전2동 600m, 덮밥/고기덮밥, 예산 5,000만원, 개점 목표 30일 |
| 목표 | 입력부터 브랜드 생성, 프랜차이즈 비교, 입지, 4개월 회계, 상담 CTA, 점주 전환 미리보기까지 한 번에 흐르게 만들기 |
| 제외 | 사용자가 전국 임의 주소를 넣는 on-demand 실제 수집, 모든 업종의 완전한 프랜차이즈 평균 |
| 이유 | 오픈채팅 초기 반응 검증에는 `넓은 데이터`보다 `한 시나리오의 설득력 있는 완주`가 더 중요 |

### 2-2. 2차 오픈채팅 체험 범위

2차는 업종 선택 체험을 넓힌다.

| 확장 항목 | 목표 |
| --- | --- |
| 업종 | 현재 11개 업종 유지, 각 업종별 대표 프랜차이즈 공개 표본 10~20개 보강 |
| 입지 | 부산대 외 2~3개 상권 추가, 예: 대구 반월당, 서울 홍대/연남, 경기 수원역 |
| 상담 | 시공사/컨설턴트/홍보채널 상담자 2~3명 등록 전까지는 `입주 예정` 상태로 리드만 저장 |
| 점주 전환 | 실제 결제 전에는 `3개월 무료 대시보드 예약` CTA로 운영 |

## 10. 최종 결정

오픈채팅에 올릴 1차 데모는 `여러 업종을 얕게 보여주는 데모`가 아니라 `부산대 장전2동 고기덮밥 창업을 실제처럼 끝까지 검토하는 데모`로 가야 한다.

현재 앱의 가장 큰 약점은 UI가 아니라 `프랜차이즈 비교 데이터 부족`과 `선택한 입지가 회계/상담/타임테이블로 끝까지 이어지지 않는 상태 단절`이다.

다음 턴 구현의 P0 목표는 `고정 점포 1개 기준으로 예비점주가 프랜차이즈 상담 전 의사결정을 할 수 있는 완주형 리포트`를 만드는 것이다.
